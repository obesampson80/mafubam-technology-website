Portfolio Project case study

Machine condition analysis dashboard

A research analytics project that turned vibration recordings into feature tables, model comparison results, report figures and a small demonstration interface for explaining machine-condition predictions.

Project type
Research data analysis and prototype support
Focus
Predictive maintenance, signal features, model evaluation
Outputs
Notebook workflow, figures, metrics, demo screens
Status
Public-safe version; identifying details changed
01

The Brief

The project needed to show whether machine-condition recordings could be processed into useful fault-detection evidence.

The client already had a research direction, but the work needed a stronger technical path: prepare the data, create features, compare models, export clear figures and make the result easier to demonstrate. The page shown here is not the original submission. It is a recreated public version that keeps the shape of the work while changing private details.

02

The Challenge

The raw analysis could not be presented as isolated code output. It needed a clear result story.

Data volume

Signal recordings had to be split into comparable windows before any reliable summary could be shown.

Result clarity

Model metrics, charts and prediction evidence needed to be readable by a reviewer who was not inside the code.

Honest interpretation

Strong primary results had to be separated from weaker checks so the report did not overstate the outcome.

03

Analysis Flow

Prepare

Organised machine-condition records into consistent groups and windows for analysis.

Extract

Built feature tables from signal behaviour so the models had structured input.

Compare

Reviewed classifier performance with clear metrics instead of relying on one headline number.

Present

Converted the technical output into figures, tables and demo screens that could support a report discussion.

04

Interface Evidence

The demonstration screen made the project feel practical because the result could be inspected, not only described.

05

Outcome

The final project became easier to review because the notebook, figures, metrics and interface supported the same story.

Clearer evidenceSignal features and prediction summaries were presented in a way that connected the data to the result.
Better report flowFigures and explanation notes were arranged around the research objective, not around raw software output.
Demo-ready presentationThe interface helped the project feel active and inspectable during review or defence preparation.
